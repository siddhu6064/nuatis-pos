CONTEXT
Wrinkle framework closed at B23 (money/state/duration all validated). Split tender currently supports card + cash on a single transaction via the payments[] array, with mock-void disclaimer on cancel-after-card-charged. The N-leg shape has only been exercised at N=2 with mixed methods. This batch extends the split-tender modal to support multiple card legs (and any combination up to a sane cap), validating the remainder-state machine under stress. Production scenario: first card declines or has insufficient balance for the partial, customer hands over a second card to cover the gap.

GOAL
A single transaction can be settled across up to 5 payment legs in any combination of card + cash, with each card leg running its own simulated reader cycle and a running ledger of captured legs visible in the modal.

SCOPE — BUILD THIS
- Extend split-tender modal state machine: after a card leg captures, modal returns to leg-picker with running ledger visible; user can tap Card again or Cash again or Comp.
- Running ledger UI inside split modal: each captured leg shown in capture order with method, amount, mock last4 (cards only). Format like "Card · $40.00 · ****4242" stacked vertically. Below the ledger: "Remaining: $XX.XX" line in the same JetBrains Mono / accent style as elsewhere.
- payments[] array supports N entries with method='card' (validate this is currently structurally allowed; if any code paths assume max-one-card, fix them).
- Each card leg runs the existing 2-second simulated reader animation independently (same component, re-triggered per leg).
- Each cash leg runs the existing right-to-left cents-fill keypad independently, defaulting amount to current remainder.
- Cap total legs at 5. Attempting a 6th leg shows toast "Maximum 5 split legs per transaction" and blocks. The remaining-amount input on the 5th leg should auto-fill to the full remainder so the 5-leg cap can always settle a transaction.
- Cancel mid-flow after one or more card legs already captured: mock-void disclaimer modal lists every captured card leg by amount and last4, with text noting that in production all captured charges would be reversed via Stripe Terminal void API. Confirming cancel discards all captured legs and returns to cart.
- Receipt rendering (Receipt.tsx): payments section lists each leg in capture order with method, amount, and mock last4 for cards. No structural change to the rest of the receipt.
- Today's Sales receipt detail view: same leg ledger renders in the detail panel below the line items, in capture order.
- Transaction list badge: existing SPLIT badge unchanged. Multi-card-only transactions still get SPLIT (no new badge).
- Per-staff revenue math: unchanged. Line-level staff attribution drives the per-staff breakdown; the payment mix is independent of who gets credited.
- Payment mix breakdown in Today's Sales totals: each card leg counts toward "Card" total, each cash leg toward "Cash" — N card legs aggregate cleanly into one card column.
- Mock last4 generation: per-leg, generated at capture time, four random digits prefixed with **** for display. Stored on the leg, not regenerated on render.
