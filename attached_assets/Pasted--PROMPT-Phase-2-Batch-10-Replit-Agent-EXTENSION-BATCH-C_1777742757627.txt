SCOPE — BUILD THIS — DISCOUNT > 20% GATE

4. lib/cartMath.ts — add `MANAGER_DISCOUNT_THRESHOLD = 20` constant.

5. components/CartLine.tsx discount picker behavior:
   - When operator selects [Custom] and enters >20, the value is staged but NOT yet applied. Apply button text changes to "Apply (Manager)" and applies a small lock icon (text "🔒" or "M" badge) styling.
   - Tapping Apply → invoke `requestManagerOverride(\`Line discount of \${value}%\`)` → on approval, set discountPercent on the line; on rejection/cancel, clear staged value, picker stays open.
   - Same gate for preset chips? — keep it simple: presets cap at 20% (no preset >20). Custom is the only path to >20, which routes through the gate.

7. Reducing or removing a manager-approved discount (back to ≤20% or 0) does NOT require re-approval. The gate fires on UPGRADING into manager-required range, not on downgrading out.

SCOPE — BUILD THIS — REFUND FLOW

8. ReportsOverlay receipt detail mode (Batch 6) gets a new button — "Refund" — added to the right column above or alongside the [Print] [Email] [SMS] [Close] re-delivery row. Visible only when transaction is NOT already fully refunded. Distinct styling: white background, red border #DC2626, red text. Same height as re-delivery buttons.

9. Tapping Refund triggers `requestManagerOverride('Refund authorization')`. On approval → transition the receipt detail mode into a refund picker mode within the same overlay. On reject/cancel → no change, stay in receipt detail.

10. Refund picker mode (in-overlay, replaces the receipt panel temporarily):
    - Title: "Refund Items" (Fraunces 700, 22px)
    - For each line item in the transaction: a tappable row with a checkbox left, line description (service name + qty × price + staff name) center, line total right. Tapping the row toggles checkbox.
    - "Refund All" toggle at top — checks/unchecks all rows in one tap
    - Live "Refund Total" footer at bottom: shows selected lines' total + their proportional tax allocation. Tip NOT refunded (rule: tip is voluntary).
    - Two buttons bottom: [Cancel] and [Confirm Refund $X.XX] — Confirm disabled when no lines selected
    - Cancel returns to receipt detail mode (no refund processed)

11. Confirm Refund tap → 1500ms simulated processing overlay (smaller than full-screen — just a dimmed backdrop with "Processing refund..." centered) → on completion:
    - Update the transaction in nuatis-pos:transactions: add `refunds: [{ id, refundedAt, lineIds: [], lineRefundCents, taxRefundCents, totalRefundCents, managerOverride: true }]` (array — supports multiple partial refunds, but for prototype just append)
    - Add `refundedTotalCents: number` (cumulative across all refunds on this transaction)
    - Toast "Refund processed (mock)" — same Toast component
    - Return to receipt detail mode, which now reflects the refund state

12. Refund math:
    - Sum selected line totals (already discount-applied) = lineRefundCents
    - taxRefundCents = Math.round((lineRefundCents / originalSubtotalCents) × originalTaxCents) — proportional
    - totalRefundCents = lineRefundCents + taxRefundCents
    - NO tip refund

13. Receipt detail rendering after refund:
    - Show "PARTIALLY REFUNDED" or "FULLY REFUNDED" stamp top-right in red (rotated -8deg, same pattern as COMPED)
    - Below totals, show refund row(s): "Refund #1: −$X.XX" with date/time
    - Show "Net: $X.XX" final line
    - Refunded line items shown with strikethrough on the receipt
    - Refund button hidden when fully refunded; visible when partially refunded (allows additional refund up to remaining)

14. Today's Sales transaction list — refunded transactions visibly flagged:
    - Red "REFUNDED" or "PARTIAL" badge inline next to time/customer
    - The transaction's displayed total stays the original (don't subtract refund — confusing to operator scanning the day's sales). But add a small muted sub-line "Refunded $X.XX" below the row when applicable.

15. Today's Sales summary stats:
    - Add "Refunds: −$X.XX" as 5th stat (color #DC2626) — sum of all refunds today
    - Net Revenue (informational, smaller): subtract refunds from Revenue stat. Display as small line under Revenue: "Net: $X.XX" (Epilogue 400, 12px muted) — only shows when refunds > 0
    - Per-staff revenue subtracts refunds proportionally: when a refund affects line X attributed to staff Y, deduct that line's refund amount from staff Y's revenue. Comped tickets unchanged ($0 contribution).

16. Per-staff transaction count: refunded-but-not-fully-refunded transactions still count as 1 transaction for the staff. Fully-refunded transactions still count (don't pretend they didn't happen).
