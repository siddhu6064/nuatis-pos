▶ PROMPT [Phase 2 · Batch 3 · Replit Agent]

CONTEXT
Continuing the throwaway UX prototype for Nuatis POS. Stack is React 18 + Vite + Tailwind v4 (deviated from Next.js 14 / Tailwind v3 spec — fine for prototype, won't carry into production). Batch 1 shipped auth + register grid. Batch 2 shipped the right-side cart with quantity controls, 8.25% tax, integer-cents math, and localStorage persistence at key `nuatis-pos:cart`. Tapping Charge currently just console.logs.

This batch adds tip selection (in-place within cart) and the mock checkout flow: simulated card reader → success → New Sale clears and returns to register. Tip selection uses presets [No Tip, 15%, 18%, 20%, 25%, Custom]. Tip is calculated on subtotal only (NOT subtotal+tax). Production will use Stripe Terminal exclusively — for prototype, Card-only mock is sufficient.

GOAL
With items in cart, tapping Charge transforms the cart into tip-selection mode in place; selecting a tip and tapping Confirm Charge launches a full-screen simulated card reader for 2 seconds, then a success screen with "New Sale" button that clears everything and returns to the register grid.

SCOPE — BUILD THIS
1. Checkout state machine in hooks/useCheckout.ts: states 'idle' | 'tip' | 'processing' | 'success'. Transitions: idle→tip (tap Charge), tip→idle (tap Cancel), tip→processing (tap Confirm), processing→success (after 2000ms setTimeout), success→idle+clear (tap New Sale).
2. In 'tip' state, cart panel shows a tip preset row above the math summary: 6 buttons in a single horizontal row — [No Tip] [15%] [18%] [20%] [25%] [Custom]. Each button ~52px tall, equal width. Selected preset gets accent border + bold text. No preset selected at start (No Tip is the rest state showing tipCents=0).
3. Selecting 15/18/20/25 sets tipCents = Math.round(subtotalCents × pct). Total updates immediately.
4. Selecting [Custom] reveals an inline numeric input below the preset row: "$" prefix + text input. Accepts dollars-cents like "5.00" or "5" or "12.50". Validate: numeric only, max two decimals, no negatives. "Apply" button next to input commits the value. Empty/invalid input shows "Apply" disabled.
5. Math summary in tip state: Subtotal row, Tax row, Tip row (hidden when tipCents=0, visible otherwise), Total row. All fonts as in Batch 2.
6. Tip math: tipCents calculated on subtotalCents only — NEVER on subtotalCents+taxCents. totalCents = subtotalCents + taxCents + tipCents.
7. "Charge" button (idle) becomes "Confirm $X.XX" (tip state) — shows live total reflecting current tip selection. A small "Cancel" text link sits above or below — tapping returns to idle, cart and items intact.
8. Confirm Charge tap → full-screen overlay (fixed position, z-50, covers header + grid + cart). Background #0F0F10 (near-black). Centered content:
   - Top: "Present card to reader" (Epilogue 600, 24px, white)
   - Middle: animated indicator — three dots cycling opacity 0.3→1.0→0.3 in sequence, 1200ms loop, pure CSS
   - Bottom: total amount (Fraunces 700, 56px, white)
9. After 2000ms, transition to success state without user action:
   - Green checkmark — pure CSS or inline SVG, ~80px diameter, brief fade-in (200ms)
   - "Approved" (Epilogue 600, 32px, white)
   - Charged amount (Fraunces 700, 56px, white)
   - "New Sale" button — full-width-ish (max 320px), 56px tall, accent #E84A00, white text, Epilogue 600, 18px
10. New Sale tap → dismiss overlay, clear cart from state + localStorage, reset checkout state to 'idle', return to register grid with empty cart.
11. On success transition, append the completed transaction to localStorage key `nuatis-pos:transactions` as an array. Transaction shape: { id: crypto.randomUUID(), lineItems, subtotalCents, taxCents, tipCents, totalCents, paymentMethod: 'card', completedAt: new Date().toISOString() }. Cap array at last 10 transactions (drop oldest on overflow).
12. Extend lib/cartMath.ts with `calcTip(subtotalCents, percent): number` (returns integer cents) and update `calcTotal` signature to take tipCents. Existing TAX_RATE constant unchanged.
13. console.log on success: full transaction record. (For future Z report.)
