▶ PROMPT [Phase 2 · Batch 14 · Replit Agent — EXTENSION BATCH · OWNER UX]

CONTEXT
Continuing the throwaway UX prototype for Nuatis POS. Stack: React 18 + Vite + Tailwind v4. Batches 1-13 complete: full operator loop including discounts, comp, refunds, manager PIN, multi-vertical engine across salon + spa + nail bar (launch trio). Repo on prototype/replit-day-1 branch.

Every batch so far has validated OPERATOR UX — the staff member ringing tickets. This batch is the first non-operator surface: SETTINGS for the owner. Validates a different mental model entirely. Different user, different rhythm, different visual hierarchy. Form-heavy admin pattern that production needs for tax config, tip preset config, business identity edit, staff CRUD. Edits persist per-vertical to localStorage; Receipt + math reads dynamically from the edited config rather than hardcoded constants.

Locked: Settings is a SEPARATE OVERLAY accessed from the Account dropdown in the header (NOT a route, NOT a tab). All edits scoped to active vertical only. Edits are persisted per-vertical to localStorage and override the config defaults from lib/verticals.ts. Reset-to-default available per section.

GOAL
Owner taps Account dropdown → "Settings" → modal overlay opens. Three tabs: Business Identity, Tax & Tips, Staff. Each tab is a form-heavy admin surface. Edits persist to nuatis-pos:{verticalId}:settings localStorage key, override the static lib/verticals.ts defaults at runtime, and propagate through Receipt rendering, tip presets, tax math, and staff list. Per-vertical scoping — editing salon's tax rate doesn't affect spa or nail bar.

SCOPE — BUILD THIS — SETTINGS FOUNDATION

1. Type definition — extend lib/storage.ts with settingsKey(verticalId) → \`nuatis-pos:\${verticalId}:settings\`.

2. lib/verticalSettings.ts (new):
   export type VerticalSettings = {
     business: { name: string; address: string; phone: string };
     taxRatePercent: number;            // e.g. 8.25
     tipPresets: number[];              // e.g. [15, 18, 20, 25]
     staff: Array<{ id: string; firstName: string; role: string; active: boolean }>;
   };
   - getVerticalSettings(verticalId, defaultsFromConfig): VerticalSettings — reads localStorage, falls back to defaults from VERTICALS[verticalId]
   - setVerticalSettings(verticalId, settings): void — writes to localStorage
   - resetSection(verticalId, section): void — clears one section, falls back to default
   - resetAll(verticalId): void — clears entire settings entry for that vertical
   - Default tipPresets: [15, 18, 20, 25] (matches existing TipPicker)
   - Default staff: pulled from STAFF constant in lib/staff.ts (3 staff)
   - Default business + taxRatePercent: pulled from VERTICALS[verticalId]
   - Defaults are read once at runtime — config is the source of truth, settings layer is the override

3. hooks/useVerticalSettings.ts — reads + persists active vertical's settings, exposes:
   - settings: VerticalSettings (always returns a usable value, never undefined)
   - updateBusiness(business)
   - updateTaxRate(percent)
   - updateTipPresets(presets)
   - updateStaff(staffArray)
   - resetSection(section)
   - resetAll()
   - Re-reads on activeVerticalId change

4. Wire across the app:
   - Receipt.tsx reads business identity from useVerticalSettings, NOT from config directly
   - useCart / cartMath reads taxRatePercent from useVerticalSettings — TAX_RATE constant becomes a fallback default only
   - TipPicker reads tipPresets from useVerticalSettings; falls back to [15,18,20,25] if empty
   - Staff list (header switcher, per-line picker, customer search modal use? — only header + per-line picker) reads from useVerticalSettings.staff filtered to active === true
   - useActiveStaff initialization fallback: if persisted activeStaffId is no longer in active vertical's active staff list, default to first active staff in the list
