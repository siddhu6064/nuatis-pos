▶ PROMPT [Phase 3 · Batch 26 · Replit Agent]

CONTEXT
Wrinkle framework closed at B23 (money/state/duration). Multi-leg split tender closed at B24. Docs wrapped at B25 (v0.0.7-prototype). This batch validates shift-state as a wrapping envelope around register transactions — a new mental model: the register has a per-vertical "open shift" state distinct from device session (OIDC) and operator identity (active staff). Transactions during a shift get a shiftId stamp. Starting cash float is captured at open without entering Z-tape / drawer reconciliation territory (declined, hardware-dependent).

GOAL
Operator must open a shift before checkout; shift state visible in header with live duration; transactions stamped with shiftId; End Shift modal summarizes the shift before closing.

SCOPE — BUILD THIS
- New lib/shifts.ts: Shift type { id, verticalId, openedByStaffId, openedByStaffName, startedAt, endedAt?, startingCashCents } plus localStorage helpers. Two new keys per vertical: nuatis-pos:{verticalId}:currentShift (single open shift, may be null) and nuatis-pos:{verticalId}:shifts (closed shift history array, append-only).
- New useShift hook (single hook, no provider — same pattern as useCart): openShift(staff, startingCashCents), closeShift() returning a summary object, currentShift state, isShiftOpen boolean. Hook hydrates currentShift from localStorage on mount; persists on every mutation.
- Header shift pill rendered next to existing header pills: when open, "Shift · {staffName} · {duration}" using formatElapsed-style render-on-pull (NOT setInterval). When closed, "No shift open" with reduced opacity. Respects mutual-exclusivity with other header overlays.
- Account dropdown gains two conditional items: "Start Shift" visible only when no shift open; "End Shift" visible only when shift open.
- StartShiftModal: active staff preselected as opener (small swap link uses existing Switch Staff pattern); reuses the existing cash keypad component for starting cash entry (do not duplicate); "Skip starting cash" button stores 0; Confirm opens shift; Cancel closes modal.
- EndShiftModal: shows opened at HH:MM, closed at HH:MM (computed at modal open), duration, opener staff name, count of transactions during shift, gross revenue during shift (sum of totalPaid for shift-scoped service+deposit transactions, refund-aware), payment mix breakdown by leg method for shift-scoped transactions only. Confirm closes shift and writes to history; Cancel reopens dropdown.
- Register-level checkout gate: Charge button (idle state) plus Card / Cash / Split / Comp buttons (tip state) all disabled with tooltip "Open a shift to transact" when no current shift. Tile taps still allowed (cart can be built; only checkout actions gated).
- Transaction stamp: every completed transaction (service or deposit) carries shiftId === currentShift.id at write time. Pre-B26 transactions without shiftId tolerated by read-side code (no migration script).
- Per-vertical scoping: switching verticals to one with no open shift shows "No shift open" pill and gates checkout independently. Each vertical has its own currentShift slot.
- Vertical switcher gate unchanged: existing cart-state and checkout-state gate stands; shift state does NOT independently block switching (open shift in vertical A is fine when switching to vertical B).
- Optional Transaction.shiftId field on the Transaction type. Read paths that compute payment mix or per-staff totals do NOT filter by shift unless inside the EndShiftModal summary.

- Vertical switch with cart items: existing cart-state gate still fires (shift state does not block switching independently).
