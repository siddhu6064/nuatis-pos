CONTEXT

Adds Spa vertical (12 hardcoded services + modifiers + business identity) and a header vertical switcher. Per-vertical localStorage namespacing — cart, transactions, held tickets are isolated per vertical. Active staff is shared across verticals. GOAL
Operator sees a vertical pill in the header showing current vertical (Salon | Spa). Tapping it opens a switcher modal listing both verticals. Switching Spa ↔ Salon swaps the entire register grid + colors + business identity on receipts + per-vertical cart/transactions/held-tickets state. Active staff and operator session persist across switches. The switcher is gated — disabled if cart has items or checkout is non-idle.

SCOPE — BUILD THIS — ACTIVE VERTICAL STATE + NAMESPACED STORAGE

6. hooks/useActiveVertical.ts — persists active vertical id to localStorage key `nuatis-pos:activeVerticalId`. Default 'salon' on first load. Provides { activeVerticalId, setActiveVerticalId, config } where config = VERTICALS[activeVerticalId].

7. lib/storage.ts (new) — centralize localStorage keys behind small helpers:
   - cartKey(verticalId) → \`nuatis-pos:\${verticalId}:cart\`
   - transactionsKey(verticalId) → \`nuatis-pos:\${verticalId}:transactions\`
   - heldTicketsKey(verticalId) → \`nuatis-pos:\${verticalId}:heldTickets\`
   - Constant: ACTIVE_STAFF_KEY = 'nuatis-pos:activeStaffId' (shared, no vertical prefix)
   - Constant: ACTIVE_VERTICAL_KEY = 'nuatis-pos:activeVerticalId'

8. ONE-TIME MIGRATION on first load — in lib/storage.ts, exported runMigrations() called from App mount:
   - If `nuatis-pos:cart` exists → copy value to `nuatis-pos:salon:cart` (only if salon key doesn't already exist) → delete old key.
   - Same for `nuatis-pos:transactions` → `nuatis-pos:salon:transactions`.
   - Same for `nuatis-pos:heldTickets` → `nuatis-pos:salon:heldTickets`.
   - Idempotent: re-running does nothing if old keys already absent.
   - Wrap in try/catch — silent migration; log to console only on error.

9. hooks/useCart.ts — read/write to cartKey(activeVerticalId). When activeVerticalId changes, useCart reloads cart state from the new namespace. Don't merge or copy across — they are isolated.

10. hooks/useCheckout.ts — write transactions to transactionsKey(activeVerticalId). On read (Today's Sales overlay), reads from current vertical's namespace.

11. lib/heldTickets.ts — all functions take verticalId param OR read from active vertical (cleaner API: take activeVerticalId as a function parameter). Read/write to heldTicketsKey(verticalId).

12. Cart line tile-tap rule — services from lib/verticals.ts via active config. Services injected from active vertical config replace direct imports of lib/services.ts in components (or services.ts re-exports the salon list for backwards compat — your call, just be consistent).
