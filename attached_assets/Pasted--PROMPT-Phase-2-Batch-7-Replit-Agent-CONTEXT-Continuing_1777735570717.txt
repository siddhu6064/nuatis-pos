GOAL
Operator can attach modifier add-ons (e.g. "Olaplex Add-on +$25") to specific cart lines via an inline picker on the line. Operator can also Hold the current ticket (preserves cart + customer + per-line staff to localStorage), and Resume any of up to 5 held tickets from a header pill that lists held tickets.

1. lib/modifiers.ts — Map of service IDs to applicable modifiers. Use the EXACT service IDs from lib/services.ts (don't invent new ones). Example shape:
   export type Modifier = { id: string; name: string; priceCents: number };
   export const MODIFIERS_BY_SERVICE: Record<string, Modifier[]> = {
     // map keyed on service.id from lib/services.ts
   };
   Define modifiers as follows (map to whatever service IDs match):
   - Women's Cut: [{ id: 'wash_style', name: 'Wash & Style', priceCents: 1500 }]
   - Men's Cut: [{ id: 'beard_addon', name: 'Beard Trim Add-on', priceCents: 1500 }]
   - Highlights Full: [{ id: 'olaplex', name: 'Olaplex Add-on', priceCents: 2500 }, { id: 'toner', name: 'Toner', priceCents: 1500 }]
   - Color Root: [{ id: 'olaplex', name: 'Olaplex Add-on', priceCents: 2500 }, { id: 'long_hair', name: 'Long Hair', priceCents: 2000 }]
   - Gloss: [{ id: 'olaplex', name: 'Olaplex Add-on', priceCents: 2500 }]
   - All other 7 services: empty array (no modifiers).
   Export getModifiersForService(serviceId): Modifier[].

2. CartLine shape extended — add `modifiers: Modifier[]` field. Default empty array on new lines from tile tap. Migrate persisted carts on load: missing modifiers field → default to [].

3. Cart line tile-tap dedupe rule UPDATED: tile tap increments existing line ONLY if that existing line has zero modifiers AND same serviceId AND same staffId. If existing line has modifiers, append new line instead. Fresh new line always starts with modifiers=[].

4. Per-line modifier UI in components/CartLine.tsx — below the existing "→ <Staff>" label, add a small "+ Add-ons" text link (Epilogue 400, 12px muted) IFF getModifiersForService(line.serviceId).length > 0. If no applicable modifiers, omit the link entirely.

5. Tapping "+ Add-ons" reveals an inline modifier picker replacing the link — each applicable modifier rendered as a toggleable chip: "<Name> +$<price>" (Epilogue 500, 12px). Toggle state controlled by whether the modifier id is present in line.modifiers. Active chip: accent #E84A00 border + bold. Inactive chip: thin muted border. Tap any chip toggles its presence in the line's modifiers array. A small "Done" text link or ✕ closes the picker (collapses back to the "+ Add-ons" link, or shows "<count> add-ons ▾" when at least one is selected — tappable to reopen).

6. Math update — line total now = (line.priceCents + sum of line.modifiers[].priceCents) × line.quantity. Update calcSubtotal in lib/cartMath.ts to use this formula. Tax and tip math unchanged (computed on subtotalCents).

7. Receipt rendering — for each line item, render modifiers as indented sub-rows beneath the service name row. Each modifier row: "  + <Name>" left (Epilogue 400, 12px muted) + "+$<price>" right (JetBrains Mono 400, 12px muted). Indent visually with left padding. Per-line subtotal in the receipt should reflect (base + modifiers) × qty.

8. Per-staff reports update — calcPerStaffSummary in lib/reports.ts now sums (line.priceCents + modifier total) × quantity for each line where line.staffId matches. Modifiers contribute to the staff's revenue.

9. Modifier picker freezes during checkout (tip / processing / receipt / completed states) — same pattern as quantity controls in Batch 3. Operator cannot toggle modifiers mid-checkout.

SCOPE — BUILD THIS — HOLD/RESUME

10. lib/heldTickets.ts — pure storage helpers:
    - export type HeldTicket = { id: string; heldAt: string; customer: CartCustomer | null; lineItems: CartLine[] };
    - getHeldTickets(): HeldTicket[] — read from localStorage `nuatis-pos:heldTickets`, parse, default [] on error
    - holdTicket(ticket): void — push to held list, cap at 5 (drop oldest on overflow), write to localStorage
    - resumeTicket(id): HeldTicket | null — read held by id, remove from list, return the ticket
    - removeHeldTicket(id): void — remove without resuming (in case of "discard")

11. Hold action — in cart panel, add a "Hold Ticket" text link near the "Clear" link in the cart header row (or just below). Visible IFF cart has at least 1 line item AND checkoutState === 'idle'. Tap → snapshot { id: crypto.randomUUID(), heldAt: ISO timestamp, customer, lineItems } → holdTicket(snapshot) → cart.clear() → toast "Ticket held" (1500ms).

12. "Held: N" pill in header — to the LEFT of the "Today's Sales" link, add a "Held: <count>" pill (smaller, accent #E84A00 background, white text, rounded-full, ~10px font). Visible only when held count > 0. Tap opens HeldTicketsModal. Disabled when checkoutState !== 'idle' (same gating as Today's Sales link).

13. components/HeldTicketsModal.tsx — centered modal, dim backdrop. Lists held tickets, newest first. Each row:
    - Top row: time held (HH:MM AM/PM, JetBrains Mono 500 14px) — customer name or "Walk-in" (Epilogue 500 14px) — total "$X.XX" right (Fraunces 600 16px)
    - Bottom row: "<N> items" + first staff name or "Multiple" if >1 distinct staffId (Epilogue 400 12px muted)
    - Right side of row: [Resume] button (accent #E84A00, 36px tall, white text) + small ✕ for discard
    - Tapping Resume:
      - If current cart has items: prompt confirmation modal "Replace current cart? Resume will discard current cart." with [Replace] [Cancel] buttons. Replace → cart.clear() then load held ticket into cart (lineItems + customer); held ticket removed from list; modal closes.
      - If current cart is empty: load held ticket directly without confirmation; remove from list; modal closes.
    - Tapping ✕ (discard): confirmation toast or inline "Discard ticket?" → confirm removes from list without loading.
    - Empty state: never shown — pill is hidden when count is 0, so modal won't open.
    - ESC + backdrop click dismiss.

14. Held ticket persistence verified across page refresh — held tickets array survives refresh, modal repopulates from localStorage on open.

15. Active staff is NOT restored on resume — only line-level staffId is restored. Header continues showing whoever is currently active.
