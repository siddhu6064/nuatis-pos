CONTEXT
Day's prior wrinkle framework (money/state/duration) is exhaustive along the service-line-shape axis (how a single line behaves within a same-visit ticket). The production master (PRD §8.4, MVP §16.5) surfaces a separate axis untouched by the prototype: ticket-lifecycle shape. P11 Tier 4 Drop-Off (laundry, tailoring, shoe_repair, jewelry_repair) introduces the two-stage workflow — drop-off creates an open ticket without payment; ticket persists across visits; pickup hydrates the open ticket into a normal checkout flow. Same pattern is reused by P8 pet boarding/daycare and P10 auto/bike repair. This batch validates the round trip with one vertical (laundry) so the engine config can scope ticket lifecycle to specific verticals.

GOAL
Add laundry as a 7th vertical with workflow='drop_off'. Operator can drop off goods (no payment, tag assigned, customer required), see the open ticket persist in a header pill + overlay, mark it ready (mock-SMS toast), then pick it up (cart hydrates, normal checkout flow completes the ticket). The same-visit flow for all 6 prior verticals is unchanged.

SCOPE — BUILD THIS
- New laundry vertical config registered in lib/verticals.ts. workflow: 'drop_off' added to VerticalConfig type; existing verticals get workflow: 'same_visit' default. Color palette: muted blue + bronze accents, distinct from tanning's warm gold. customerTerm='customer', staffTerm='staff', serviceTerm='order' (per PRD §8.4.1).
- New lib/laundry-services.ts: 12 services. 8 fixed-price (Wash & Fold Small $15, Wash & Fold Medium $25, Wash & Fold Large $40, Dry Clean Shirt $7, Dry Clean Suit $25, Comforter $30, Wedding Gown $120, Iron-Only $5) + 4 add-on style fixed-price (Same-Day Rush $10, Hypoallergenic Detergent $3, Plastic Garment Bags $2, Stain Treatment $5). Per-pound math is intentionally skipped — covered by the tanning per-minute pattern already; this batch is about lifecycle, not pricing math.
- New lib/laundry-customers.ts: 4 seed customers (no pet fields).
- New OpenTicket type in lib/openTickets.ts: { id, verticalId, tag, customerId, customerName, lines (CartLine[]), droppedOffAt, markedReadyAt?, pickedUpAt?, status: 'in_progress' | 'ready_for_pickup' | 'picked_up' }.
- New localStorage keys per vertical (only laundry uses them in this batch but the helpers are vertical-parameterized): nuatis-pos:{verticalId}:openTickets (active in_progress + ready_for_pickup, full record), nuatis-pos:{verticalId}:closedTickets (picked_up, cap last 50), nuatis-pos:{verticalId}:tagCounter (sequential int).
- Tag generation: sequential per-vertical, format "LAUN-{0001-padded}", increments on each drop-off. Counter persists in localStorage.
- New useOpenTickets hook (single hook, no provider — pattern matches useCart/useShift): openTickets list, dropOff(customerId, customerName, lines) returns ticket with tag, markReady(ticketId), pickUp(ticketId) returns lines for hydration, completePickup(ticketId, transactionId) moves to closedTickets.
- Engine routing in pages/RegisterPage.tsx: when activeVertical.workflow === 'drop_off' AND no cartMeta.openTicketId set, the cart's primary action becomes "Drop Off" instead of Charge. When cartMeta.openTicketId is set, primary action returns to normal Charge / Card / Cash / Split flow (pickup mode). Tile taps and cart line management unchanged.
- Drop Off button gating: requires customer attached. If no customer, button shows tooltip "Customer required for drop-off" and does not advance. Drop Off also requires shift open (existing rule from B26).
- DropOffSuccessOverlay: replaces success-overlay shape for drop-off completions. Shows tag prominently (large JetBrains Mono, accent color), customer name, line items list, "Copy Tag" button (clipboard write + toast confirmation), Done button. No payment, no tip, no receipt delivery channels.
- Header "Open: N" pill: count of in_progress + ready_for_pickup tickets for current vertical. Always visible when count > 0; hidden when 0. Same affordance shape as existing Held: N pill. Respects mutual-exclusivity rule.
- OpenTicketsOverlay: list of open tickets sorted by droppedOffAt desc. Each row shows tag (mono), customer name, dropped-off relative time (render-on-pull, no setInterval), line summary count ("3 items"), status badge. Two action buttons per row: "Mark Ready" (in_progress only) and "Pick Up" (both states). Adds Open Tickets to the header overlay rotation: Waitlist / Appointments / Today's Sales / Settings / Open Tickets — now 5-way mutual exclusivity.
- Status badges: IN PROGRESS (amber), READY (green) — distinct from existing transaction badges. Use the existing badge component shell.
- Mark Ready action: transitions in_progress → ready_for_pickup, sets markedReadyAt, fires mock-SMS toast "Pickup notification sent to {customerName}" matching the existing 4-channel toast pattern from receipt delivery. No real SMS.
- Pick Up action: closes overlay, hydrates cart with the open ticket's lines + auto-attaches customer + sets cartMeta.openTicketId. Cart shows a sticky banner above the line list: "Pickup mode · Tag LAUN-0001 · {customerName}" with a "Return to In Progress" button (clears cart + cartMeta.openTicketId, ticket stays open).
- Pickup checkout: standard Charge / Card / Cash / Split / Comp flow. On successful completion, openTicket transitions to picked_up via completePickup(ticketId, transactionId), moves to closedTickets, and the resulting Transaction record carries openTicketId field linking back. Transaction list badge: standard CASH/SPLIT/etc. badges apply; no new pickup-specific badge in this batch.
- Vertical switcher: laundry switchable from any other vertical per existing rules. Open tickets persist for laundry across switches; pill only shows when laundry is active. Existing cart-state and checkout-state gates on switching unchanged.
- Cart drop-off mode visual cue: cart header shows "Drop-Off Mode" subtle label when laundry vertical AND no openTicketId in cartMeta (so operator knows what Charge will do). When in pickup mode, banner replaces this.
