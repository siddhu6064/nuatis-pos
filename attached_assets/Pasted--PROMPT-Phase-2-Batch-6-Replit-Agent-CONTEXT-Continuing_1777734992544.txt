▶ PROMPT [Phase 2 · Batch 6 · Replit Agent]

CONTEXT
Continuing the throwaway UX prototype for Nuatis POS. Stack: React 18 + Vite + Tailwind v4. Batches 1-5 shipped: Replit Auth, register grid (12 salon services), right-side cart with quantity + tax + tip, simulated card reader, receipt panel + mock delivery, transaction log at `nuatis-pos:transactions`, customer attach (pre/post-sale, phone-first), per-line staff attribution. Header has "Switch Staff" + Account dropdown.

This batch adds the operator's mid-shift / end-of-day visibility — a "Today's Sales" overlay accessed from the header. Shows summary metrics (revenue, tips, count, avg ticket, per-staff breakdown) and a list of recent transactions. Tapping a transaction row swaps the overlay content into receipt-view mode with re-delivery options.

GOAL
Operator taps "Today's Sales" in the header → modal overlay shows daily summary on top + transaction list below (default: today, toggle to All). Tapping a row swaps the same overlay to a receipt detail view with [Print / Email / SMS / Close] re-delivery options. Close ✕ or ESC dismisses entirely.

SCOPE — BUILD THIS
1. Header addition — to the LEFT of the clock (or wherever fits cleanly), add a "Today's Sales" text link (Epilogue 500, 14px, accent #E84A00). Tappable. Disabled / hidden when checkout state !== 'idle' — operator must complete or cancel the current ticket before opening reports.
2. Reports overlay — components/ReportsOverlay.tsx — fixed inset-0 z-50, #0F0F10 background. Centered white panel, max-width 640px, max-height 88vh, rounded-lg, internal scroll. Two internal "view modes" managed by overlay-local state: 'summary' (default) and 'receipt' (when a transaction row is tapped).
3. Top bar of overlay (always visible):
   - In 'summary' mode: "Today's Sales" title (Fraunces 700, 22px) left + close ✕ right.
   - In 'receipt' mode: "← Back" link left + "Receipt #ABCD1234" title (Fraunces 600, 18px) center + close ✕ right.
4. Summary section (top of summary view, white card or just inline):
   - Today's date — Intl.DateTimeFormat 'medium' style (Epilogue 400, 14px muted)
   - Big revenue number — sum of totalCents across today's transactions (Fraunces 700, 48px). Format with formatCurrency.
   - 3-stat row: Transactions (count), Tips (sum tipCents), Avg Ticket (revenue / count, or "$0.00" if 0). Each: small label (Epilogue 400, 12px muted) + value (Fraunces 600, 20px).
   - Divider.
   - "By Staff" section header (Epilogue 600, 14px). For each of the 3 staff:
     - Row: name + role (Epilogue 500, 14px) left, transaction count + revenue right (JetBrains Mono 500, 14px).
     - Per-staff revenue: sum of (line.priceCents × line.quantity) across all today's transactions where line.staffId === staff.id. NO tax, NO tip allocation. Just service revenue.
     - Per-staff transaction count: count of transactions where at least one line has line.staffId === staff.id.
     - Show all 3 staff even if 0 — ($0.00 / 0 txn) is fine.
5. Transaction list section (below summary):
   - Header row: "Recent Transactions" (Fraunces 600, 18px) left + Today/All toggle right (two small pill buttons, active gets accent border + bold).
   - Default toggle: "Today". "Today" filter: tx where new Date(completedAt).toDateString() === new Date().toDateString(). "All" filter: all transactions in localStorage (capped 10 from Batch 3).
   - Each transaction row: time (HH:MM AM/PM via Intl, JetBrains Mono 500 14px) — customer name or "Walk-in" (Epilogue 500 14px) — total formatted (Fraunces 600 16px right-aligned). Below row: small muted line with "Txn #<8chars>" + delivery icon (text "P" / "E" / "S" / "—" for print/email/sms/none) + staff (first staff name, or "Multiple" if >1 distinct staffId in line items).
   - Empty state when no transactions: "No sales yet today" (Epilogue 400, 16px muted, centered).
   - Rows tappable — tap → switch overlay to 'receipt' mode with that transaction loaded.
6. Receipt detail mode (overlay 'receipt' state):
   - Renders the existing Receipt component from Batch 4 with the selected transaction's data (line items, math, customer, staff per line, payment method, etc.).
   - Below the receipt: 4 delivery buttons in a single row (smaller height ~48px, equal width): [Print] [Email] [SMS] [Close]. Print fires "Sent to printer (mock)" toast. Email/SMS reveal their inline input + Send (same validation as Batch 4) → toast on Send. Close returns to summary view.
   - Re-delivery DOES NOT update the transaction record — fire-and-forget toasts only.
   - The four delivery buttons can be tapped repeatedly (no disable after first tap, unlike the live-sale receipt). Operator might re-print AND re-email same receipt.
7. ReportsOverlay opens via: a small useState in App / RegisterPage `reportsOpen`. Header link tap sets true. Close ✕ / ESC sets false. Backdrop click closes. Disable header link when checkout state !== 'idle'.
8. Reports overlay does NOT block the existing Checkout overlay if both somehow opened simultaneously — but UX-wise the header link is gated, so this shouldn't happen.
